Interpretation pour le jury :
============================================================
- Test A : Samba AD refuse l'identification (whoami retourne anonyme/vide), prouvant que
  l'identite de l'appelant non authentifie n'est PAS reconnue.
- Test B : Samba AD retourne 0 entree pour la requete utilisateur en anonyme, alors qu'un
  bind authentifie (cf fichier ldapsearch-authenticated-ldaps) renvoie l'utilisateur attendu.
- Smb.conf est pinne 'ldap server require strong auth = yes' (cf ADR-0034 Phase 7a, RESOLU 2026-06-02).
  Verifiable : ssh dc01 'sudo testparm -s --parameter-name=\"ldap server require strong auth\"' -> Yes
- Resultat fonctionnel : aucun acces metier (lecture comptes, lecture groupes, lecture attributs)
  n'est possible en anonyme. P-001 (HIGH \"bind LDAP anonyme\") cloture par cette posture.
